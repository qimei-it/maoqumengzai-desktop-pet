# 开源策略与功能开放边界

确认日期：2026-11-12（Asia/Shanghai）。关联 [实施交接](v1-implementation-handoff.md) §2.4、§4.5、P6，[完整交友模块](social-module-v1-scope.md)，[技术方案](technical-architecture.md) §6，[验收映射](v1-acceptance-matrix.md) H-P1-04、H-P6-01～04。

本文件记录已确认的开源形态与功能开放顺序。除明确标注为已实现的部分，各项均为待实现或待验证，不作为交付证据。

## 1. 已确认的决策

1. **只交付一条客户端代码线，公开发布并开源。** 不建立“开源版 + 闭源版”两套客户端，也不以加密、混淆或隐藏接口地址作为安全边界。
2. **按能力分层开放，而不是按安装包分版本。** 本地功能免账号开放；宠物档案与云同步需绑定毛趣映画账户；交友广场仅对已绑定账户开放。
3. **账号与云端能力移至下一版。** 账号绑定、设备会话、宠物档案云同步、Outlook、跨端 DeepSeek 会话、专属宠物制作与积分不在首个公开开源版本交付；首版只保留本地宠物档案与本地工具。
4. **交友广场移出首个公开开源版本。** 页面、入口、角标与相关提醒在首版均不出现；完整范围保留在 [完整交友模块](social-module-v1-scope.md)，作为后续开放项。
5. **开放范围与节奏由服务端运营开关控制。** 调整开关不需要重新发布客户端。

## 2. 分层开放

| 层 | 能力 | 前置条件 | 由谁控制 |
| --- | --- | --- | --- |
| 本地层 | 桌宠与动画、番茄钟、饮水/休息提醒、待办、置物架、剪贴板、截图、文件转换、音乐与歌词、邮箱收件 | 无账号 | 客户端本地执行，离线可用 |
| 绑定层 | 账号绑定/解绑/退出、设备会话与撤销、宠物档案查看与选择 | 绑定毛趣映画账户 | 服务端签发短期会话，客户端只持有令牌 |
| 服务层 | 宠物档案读写与同步、新 DeepSeek 会话、专属制作与积分 | 绑定账户 + 服务端授权 | 服务端按可信身份、设备与资源归属逐次校验 |
| 运营层 | 交友广场、附近推荐、社交提醒分组、对外注册范围 | 绑定账户 + 资质与审核结论 | 服务端运营开关，默认关闭 |

- 非小程序用户可以使用全部本地层能力，这是获客入口；绑定账户后才进入绑定层与服务层。
- 交友广场不因客户端开源而对未绑定用户开放；开放标准是资质与审核路径明确，而不是前端是否显示入口。
- 运营开关只用于收缩范围；扩大范围必须同时满足服务端授权、合规审核与产品确认三项，不能靠修改客户端绕过。

## 3. 为什么不做双版本

- 客户端代码、接口地址与协议无法对使用者隐藏：抓包、解包和调试都能取得；`asar` 不是加密，只防误改、不防读取。
- 加密与混淆拦不住抓包、第三方客户端和协议仿制，能拦住的只有顺手翻包的人；收益低于维护两套构建、两套打包流程、两套更新通道与双倍测试矩阵的成本。
- 真正的资产在服务端：真实宠物档案、交友关系、专属形象生成与积分结算。客户端开源不改变这些能力的归属与计费规则。
- 保留私有构建的退路，但不提前建设：云能力统一经 `cloud-adapter` 接口接入，官方实现独立成模块；将来出现 OEM、合作方或需要保护的自研客户端资产时，只替换适配器实现与打包配置。

## 4. 仓库与发布纪律

- **公开仓库是私有主仓库的发布镜像。** 提交与合并先在主仓库完成，再同步到公开仓库；不要把包含闭源或未公开内容的历史推送到公开仓库，已推送的历史无法撤回。
- **客户端不存放任何秘密**：不写 AppSecret、私有密钥、数据库凭据、管理后台地址或内部接口。官方接口地址视为公开信息，仍需配置化，便于自建实例与测试环境切换。
- 默认配置只含公开 endpoint；真实环境值通过本地配置或构建注入，不提交版本库。
- CI 增加密钥扫描（如 gitleaks），发现疑似凭据即失败；发布前人工复核改动范围与构建产物。
- 许可证：核心代码采用 MIT 或 Apache-2.0，允许制作私有衍生与官方构建；第三方组件、引擎、图标与素材的声明沿用 [THIRD-PARTY-NOTICES](../THIRD-PARTY-NOTICES.md) 与 `resources/licenses/`。
- 名称与商标：官方名称、官方服务与域名由运营方保留；第三方构建不视为官方客户端，也不代表获得官方服务授权。
- 官方服务条款与隐私政策单独声明；许可证只覆盖代码，不覆盖线上服务与用户数据。

## 5. 客户端内的云能力接缝

- `src/main/services/cloud` 只暴露适配器接口与领域类型；官方实现单独成模块，渲染层经受限 IPC 调用，不直接持有令牌或接口细节。
- 分层由“是否注册适配器 + 服务端授权”共同决定，界面不做假入口：未绑定时不显示云端页面，而不是显示后再报错。
- 交友适配器在首个公开版本保留接口，但不注册路由与入口；后续开放时只增加实现与开关，不改本地层代码。
- 构建时注入环境标识（官方/自建），仅用于日志与客服排查，不作为权限依据。

## 6. 服务端必须承担的安全边界

- 登录使用 OAuth 2.0 + PKCE 等标准授权，签发短期 access token 与可撤销的 refresh token；令牌在本机经 `safeStorage` 保存，不写入渲染层状态或日志。
- 设备会话可列出与撤销；账号切换、退出或令牌失效后清理旧会话与相关缓存。
- 每个云端资源做归属校验：宠物档案、图片、会话、交友资料只能由本人或有授权的参与者读写，禁止只凭对象 ID 推断权限。
- 按账号、设备与 IP 限流；对新设备注册、批量请求与异常频率做风控；举报与审核链路真实落库。
- 桌面端只访问白名单业务网关（如 `/api/desktop/v1/*`）；管理、审核与内部接口不对桌面端暴露。
- 服务端日志与错误上报不包含凭据、宠物隐私字段、联系方式明文或本地工具数据。

## 7. 首个公开开源版本的范围

包含：本地层已实现能力、本地宠物档案查看/编辑/选择、必要的隐私说明。账号绑定、设备会话、宠物档案云同步、Outlook、跨端 DeepSeek 会话、专属宠物制作与积分移至下一版。

不包含：交友广场及相关页面、入口、角标、提醒分组与深链接；附近推荐与公开档案的社交互动同样不出现。相关范围与验收口径保留在 [完整交友模块](social-module-v1-scope.md)，实现前不勾选对应验收项。
