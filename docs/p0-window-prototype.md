用户本轮明确将桌面项目标识更新为 `mqmz`。IPC 使用 `mqmz:*`，配置/数据键使用 `mqmz.*`，环境变量使用 `MQMZ_*`，本地表采用 `mqmz_*`；应用 ID 为 `com.mqmz.desktop`，数据目录为 `mqmz-desktop`。普通函数和类型保持 TypeScript 常规命名。项目此前尚无已发布应用和旧前缀运行数据，本轮无需迁移已发布用户数据。

已同步项目规范、交接、技术方案与参考评估中的本项目命名约定；小程序仓库路径、参考项目标识、既有业务表与协议字段继续遵循各自语义。

## 2. 本次实际实现

- Electron 主进程、受限 preload、Vue 验证台与单独的无边框透明窗口；沙箱、上下文隔离及运行时 schema 检查。
- 布偶猫角色素材（112 DIP，448 px 帧，1024 源图）：待机、闭眼、被拎起、疑惑与听歌姿态，真实 alpha；待机做呼吸起伏、轻微摇摆与定时眨眼；检测到系统正在播放音乐时切到戴耳机的听歌姿态（缓慢摇摆），交互姿态优先；同时在桌宠上方叠一个 240×240 的透明、鼠标穿透窗口，播放 512×512、25fps、6 秒循环的白色音符 APNG（带柔和投影，浅色桌面可读），跟随桌宠移动；桌宠下方再挂一个音乐控制条（Lucide 图标，无文字）：Apple Music 显示随机、循环、上一首、播放暂停、下一首、歌词、静音；其它播放器显示上一首/播放暂停/下一首/歌词/静音。播放或暂停时显示，无会话时隐藏。宠物框内左下另有一个 32×32 窗口中的 30×30 圆形 eye-off/eye 开关，圆心与循环按钮对齐，控制控制栏显隐；播放中拖入文件/文件夹时，音符、控制条、歌词、气泡与开关全部收起，让位给投递轮盘。拖动桌宠时，歌词卡、气泡、音量滑块与音符/控制条按同一偏移实时跟随；鼠标移到静音按钮时向上弹出 40×122 的竖向系统音量滑块（与按钮水平居中、距控制条 6px，静音时归零、取消静音恢复先前音量）；点歌词按钮在桌宠上方显示高度 88 的歌词卡，宽度按当前歌曲最长一句测量并限制在 200–480，切歌时随歌词重新计算，歌词从 LRCLIB 拉取并按曲目缓存；有同步歌词时打开歌词卡后把播放位置轮询提高到 1 秒，并按采样时间补差；每句在下一句时间戳前 0.5 秒用 easeOut 快速起步、轻缓收尾地向上滚动一行（渐隐，不使用模糊阴影），渐隐强度按每行与视口中心的距离连续计算，居中行恒为 0，上一行上半部渐隐消失、下半部保持清晰，下一行上半部先清晰、下半部渐隐入场，不提供手动滚动；纯音乐显示“纯音乐”，LRCLIB 未收录时歌词按钮置灰禁用；中文歌的歌词、歌名与歌手在本地用 opencc-js 转简体，日文、韩文与英文保持原文。播放时每首歌在 20%/55%/85% 处各弹一次 216×84 的指向头顶气泡；状态提示另用 190×64 的小气泡，约 3 秒后消失（无时长时 40s/120s/210s），文案按曲风与歌名/专辑/歌词关键词判断温柔、热血、轻快、深夜、怀旧、纯音乐或通用心情，从本地模板库随机选取歌名/歌手/歌词/陪伴四个方向且同曲不重复；气泡出现时音符淡出，暂停、拖拽或控制栏隐藏时不弹；歌词卡打开时由气泡临时接管，5 秒后自动恢复歌词（整图切帧，眼部差分仅 86×41；摇摆 ±1.5°、上下 3px、4.6 秒一轮）
- 当前可见图像 alpha 命中、透明区域让出鼠标，内部封闭镂空（如肉垫）按本体处理；缺失命中数据时保持可恢复。窗口原生缩放后重新测量命中位置。
- 默认只显示透明标记。文件拖入桌宠窗口时窗口临时扩大，Filee 式十等分圆环从中心弹出：**置物架、格式转换、打包归档、解压缩、压缩大小、吃掉、另存副本、提取音频、批量重命名、智能问答**，中心是宠物、松手取消。光标所在扇区高亮并向外弹 7px；松手直接执行、面板不常驻；松手在环外或移出窗口则取消，文件保持原样。
- 宠物常驻窗口 132×156 DIP（1 倍，宠物 112×112，含下方名称“麻薯”标签），拖入后扩展为 312×312 DIP；洞口直径 136、环厚 58、外径 252，关闭后恢复。边缘由工作区约束。
- 轮盘几何移植自 Filee（MIT）：角度从 12 点顺时针、内径比 0.4286、扇区间隙、子环跨度/命中公式；颜色、字体与按钮材质改用毛趣映画 token，未复制 Filee 品牌素材。署名见 [THIRD-PARTY-NOTICES](../THIRD-PARTY-NOTICES.md)。
- 图片转换已接入：拖入 JPG / PNG / WEBP 后打开 400×460 面板，选择目标格式后由 sharp 真实转换。单个文件输出到源目录；批量按源目录建立 `convert_output/`；重名生成 `名字 (2).后缀`，源文件永不覆盖。图片也能转成 A4 PDF；多个 PDF 可合并到 `convert_output/`，单个 PDF 可按页拆分到 `convert_output/<文件名>/page-N.pdf`。Office 与音视频仍在后续阶段。
- 打包归档把本次拖入的文件打成 ZIP，放在首个源文件旁：单个文件沿用原名，批量用 `归档-时间戳.zip`，重名追加 ` (2)`，结果自动加入置物架。解压缩目前支持 ZIP，解到与压缩包同名的**新建**文件夹；解压前拒绝路径穿越、重复路径、超过 2000 个条目或解压后超过 1 GB 的包。压缩大小对 JPG / PNG / WEBP 以 82–85 质量、最长边 2560 重编码，单文件写在源目录，批量写入 `compress_output/`，源文件不覆盖。
- “吃掉”把文件移入系统应用数据目录的桌宠回收区 `belly/`，记录到期时间（7 天），置物架列出并支持“取回”；取回优先回到原路径，冲突时生成带后缀的新文件名。启动时清理到期项。
- 单击桌宠打开旁侧置物架卡片；卡片底部固定新增文件、格式转换、另存副本、移出置物架、定位源文件，文件列表按数量自适应高度并可继续滚动。主体拖动、6 DIP 起拖阈值、释放后约束工作区及本地原子保存；托盘和 `CommandOrControl+Shift+M` 恢复入口。
- 文件投递模式让整个接收区可交互；通过系统文件选择或实际 File 对象登记本地文件，拒绝虚构文件、目录、符号链接及超量输入。
- 文件记录返回 ID、名称、大小与时间；文件一进入置物架就原子写入系统应用数据目录的 `mqmz.file-shelf.json`，重启恢复，不再需要“暂存”二次确认；原件留在原处。
- 按住文件卡片本身触发系统 `webContents.startDrag`，不设“拖出”按钮；原生落入目标应用的端到端结果尚待人工核验。
- 支持系统保存选择器另存真实副本，拒绝覆盖原件及同一 inode 的硬链接目标；移除记录只删除索引。
- 置物架底部的“格式转换”直接打开转换面板；拖拽轮盘的图片与 PDF 基础转换已可用，Office 与音视频等方向仍按阶段接入。
- 第十个扇区“智能问答”在拖入文件后打开 400×520 面板（托盘菜单也可直接打开）：首次显示 DeepSeek API Key 配置页，Key 通过系统 safeStorage 加密保存在本地；未配置时不发任何外部请求。对话在 Electron 主进程请求 `https://api.deepseek.com/chat/completions`（`deepseek-flash`，关闭思考模式），把拖入的文本文件截断后作为上下文，单文件 12k、总计 40k 字符，最多 16 个文件；文件内容仅在提问时发送。错误按 401/402/429/5xx 映射为可读提示，API Key 不下发到渲染层。接口与验证记录见 [DeepSeek 智能问答接入](research/deepseek-chat.md)。
- 实时读取显示器原点、工作区、缩放；支持将窗口移到指定屏幕；显示器变化与唤醒后恢复位置。
- 读取屏幕捕获权限；用户点击后调用 `desktopCapturer` 获取真实屏幕缩略图，默认只驻留内存；另存时打开系统保存选择器。
- 生产渲染会话阻止 HTTP/HTTPS/WS/WSS 外部请求；开发模式只允许指定的本地 Vite 地址，不接入模型、邮箱、播放器或任何演示服务。

交互标记只是技术测试图形，正式布偶猫/柯基素材、完整手势/行为、框选截图与永久置物架按原阶段继续实现。

## 3. 运行与验证

```sh
npm ci
node node_modules/electron/install.js
npm run dev
```

或验证生产渲染入口：

```sh
npm run build
npm start
```

自动化：

```sh
npm test
npm run test:e2e
```

需要真实图形桌面会话。测试使用临时数据目录，截图和运行证据位于 `/tmp/mqmz-p0-*`，不提交个人屏幕内容、文件正文或凭据。`MQMZ_DATA_DIR` 只允许开发/测试覆盖默认目录；打包应用忽略该覆盖。默认运行数据位于系统本地应用数据目录下 `mqmz-desktop`。

可选 macOS 光标验证辅助程序仅移动光标，不发送点击，也不请求/修改辅助功能权限：

```sh
xcrun swiftc tests/native/macos-cursor.swift -o /tmp/mqmz-p0-cursor-helper
MQMZ_CURSOR_HELPER=/tmp/mqmz-p0-cursor-helper npm run test:e2e
```

## 6. 下一步人工操作

1. 看到交互标记后，单击主体打开旁侧文件卡片；按住主体拖到新位置，释放后重启核对保存；在透明角落点击底层应用，核对不拦截。
2. 直接把自选测试文件拖到桌宠身上：轮盘应在拖入时出现，十个扇区为置物架、格式转换、打包归档、解压缩、压缩大小、吃掉、另存副本、提取音频、批量重命名、智能问答。分别松手，核对置物架记录、转换、打包归档、解压缩、压缩大小、吃掉与另存副本的提示；在中心与环外松手应不产生记录。置物架按住文件拖到空测试文件夹，核对落地；“吃掉”后到置物架取回，核对原文件。
3. 跨两块屏幕拖动并切换 0.75/1/1.5/2 倍比例；再验证屏幕插拔、系统缩放、全屏/Space、睡眠唤醒与恢复快捷键。
4. 按需验证截图权限首次授权、拒绝/撤销/恢复和另存缩略图；这些验证截图只留本机，不上传仓库。
5. Windows 10 22H2、Windows 11、Intel Mac 与最低 macOS 13 按同样清单补证据；构建配置存在不算目标平台通过。

第 3 项当前交付的是可运行原型及部分实测证据，完整首版和 H-P0-05 仍按验收映射追踪，不跳过剩余原生/平台条件。

## 6.1 产品入口修正

用户指出大型验证台缺少产品实用性、文件应从文件本身拖动。本轮据此移除默认打开诊断台与投递后跳转诊断台的行为，使用贴近桌宠、按内容高度调整的小卡片完成当前文件操作。开发诊断台仅在未打包版本创建并从托盘的开发入口打开；它不作为正式版页面交付。

当前置物架是 P0 的最小可用实现，使用本地 JSON 索引；后续 P3 迁移至既定 SQLite 存储时须保留置物架记录。完整转换、批量、永久存储策略、权限及跨平台发布仍按原清单实现；本轮没有删减范围。
