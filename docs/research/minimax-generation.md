# MiniMax 多模态接入

日期：2026-11-16。首个公开版本只接入 MiniMax 作为 Agent 文本与生成 Provider；百炼顺延到后续版本。火山方舟只用于桌宠形象生成，不进入 Agent 模型菜单，见 `docs/research/pet-generation.md`。

## 调用入口

- 文本、图像、视频、语音模型都从智能体输入框的模型菜单选择，不再单独做创作面板。
- 文本模型也可以通过内置「图像生成 / 视频生成 / 语音生成」技能调用对应工具；工具参数由模型解析，不显示输入框参数条，每次生成都要求审批。
- 工具自动使用当前消息的媒体附件：图像工具只接受图片，视频工具接受图片/视频/音频，语音工具不接受附件；参数超限返回给模型追问。
- 设置页的 MiniMax 模型列表使用固定 6 个模型，不调用 `/models`；已配置 Key 后即可查看，不需要先做延迟测试。
- 选中文本模型时，输入框下方不显示额外参数；只有模型支持推理强度时才显示「推理强度」。
- 选中图像、视频、语音模型时，输入框下方显示一行生成参数，点开后展开设置。
- 同一个输入框既接收文本提示词，也接收参考附件；生成结果直接回到会话里预览。

## 参数

| 类型 | 参数 |
| --- | --- |
| 文本 | `MiniMax-M3.1-Flash` 支持 `low / medium / high / xhigh / max`；`MiniMax-M3` 不显示推理强度 |
| 图像 | 输出尺寸 `1K / 2K / 4K`、画面比例、输出格式、生成数量 1–10 |
| 视频 | 清晰度 `768P / 2K`、画面比例、时长 4–15 秒 |
| 语音 | 音色、语速 0.5–2、情绪、输出格式 `MP3 / WAV` |

MiniMax 视频 V2 默认生成音频，没有开关参数，因此界面不提供「生成音频」开关，避免出现无效设置。

## 接口

- 文本：`POST https://api.minimax.cn/v1/chat/completions`
  - OpenAI 兼容格式，使用 `tools` + `tool_calls`，保留 `reasoning_content` 以维持多轮工具调用。
  - `MiniMax-M3.1-Flash` 强制开启 thinking，只能调 `reasoning_effort`。
  - `MiniMax-M3` 在关闭推理时传 `thinking: { type: "disabled" }`。
- 图像：`POST /v1/images/generations`；有参考图时用 `POST /v1/images/edits`。
  - 参考图先通过 `POST /v1/files/upload`（`purpose=image_generation_input`）上传，再用 `mm_file://{file_id}` 引用。
- 视频：`POST /v2/video_generation` 创建任务，`GET /v2/query/video_generation/{task_id}` 轮询。
  - 参考图/视频/音频通过 `purpose=video_generation_input` 上传后以 `mm_file://{file_id}` 引用。
  - 单张图 + 无其他参考素材时作为首帧；两张图作为首尾帧；其余图片、视频、音频作为多模态参考素材。
  - 停止按钮会调用 `DELETE /v2/video_generation/{task_id}` 尝试取消排队任务；已在运行的任务按官方限制无法取消。
- 语音：先用 `MiniMax-M3`（关闭 thinking）把用户描述改写成可直接朗读的台词，再调用 `POST /v1/t2a_v2`，非流式，返回 hex 音频后写入本地文件。生成的台词显示在音频上方。

## 本地文件

- 生成结果默认保存在：

  ```text
  <智能体附件保存目录>/<YYYY-MM-DD>/<会话ID>/<文件名>
  ```

- 目录在生成开始时创建；同一天、同一会话复用同一目录。文件命名带时间戳与随机后缀。
- 渲染进程通过 `mqmz-media://source/<来源ID>` 预览图片、视频与音频；主进程维护来源 ID 到绝对路径的映射，避免在 URL 中暴露路径。
- 旧的 `mqmz-media://generated/<文件名>` 地址继续兼容 `userData/generated` 中的历史文件。
- 每个生成结果组上方显示「下载图像 / 下载视频 / 下载音频」链接：点击打开当前会话保存目录，悬停显示目录路径；下方消息操作行只保留一个下载图标，用于另存为。
- 图像和视频直接放在圆角容器中，贴边、无留白、左对齐；多图右侧显示缩略图切换主图。
- 生成中显示占位卡：圆角方块、点阵背景，右下角转圈加载；图片按请求数量显示多个占位卡。

## 真实验证

2026-11-16 使用真实 MiniMax Key 在 macOS 应用内验证：

- 文本：`MiniMax-M3.1-Flash` 流式回复正常；`tool_calls` 调用 `todo_list` 后返回「待办数量：2」。
- 图像：`MiniMax-H3-Image` 1K 文生图成功，生成文件通过 `mqmz-media://` 在会话内显示（1248×832）。
- 语音：输入描述后由 `MiniMax-M3` 改写台词，`speech-2.8-hd` 合成成功，音频可播放（约 4.6 秒），台词显示在音频上方。
- 视频：`MiniMax-H3` 768P / 16:9 / 4 秒任务成功，视频可播放（约 4.46 秒）。
- 新保存路径：图像与语音均落到 `附件保存目录/2026-11-16/<会话ID>/`；语音通过新来源地址正常播放。
- 生成占位卡：1:1 点阵方块、右下角转圈加载已实际显示；主题色点阵带 2.4 秒透明↔着色呼吸动画，`prefers-reduced-motion` 下静止。上方「下载图像/音频」链接和路径 tooltip 已验证。
- 多图缩略图：两张 1K 图生成后，右侧显示两张缩略图，点击可切换主图。
- 本地参考图编辑：通过剪贴板附加图片后生成成功，走 `image_generation_input` 上传与 `mm_file://` 引用。
- 视频参考图：附加图片后生成成功，视频可播放（约 4.46 秒）。
- 另存为：单文件保存到 Downloads；双图选择文件夹后两个文件均复制成功。
- 视频工具参考素材：附加本地图片后调用 `video_generate`，生成 4 秒 768P 视频成功，工具自动使用当前消息附件。
- 参数超限：请求图像工具 `count=20`，工具返回范围错误，Agent 向用户说明并追问数量，前端不弹参数错误 toast。
- 队列取消、局部失败提示尚未做真实付费验证。

## 失败处理

- Key 无效、余额不足、限流、内容审核失败和网络错误统一显示为面板提示，不写进消息正文。
- 图像部分成功时保留成功结果，并在结果下方列出失败项。
- 语音合成不支持附件；图像只接受图片参考；视频只接受图片、视频、音频参考。生成模型下输入 `@` 可把已添加的媒体附件插入为内联药丸（图1 / 视频1 / 音频1），发送时序列化进提示词。
