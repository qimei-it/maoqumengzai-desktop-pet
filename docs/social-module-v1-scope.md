# 首版完整交友模块实施范围

确认日期：2026-11-09。关联 [实施交接](v1-implementation-handoff.md) P6、[验收映射](v1-acceptance-matrix.md) H-P6-01～04，以及 H-P1-04 登录与设备会话。

用户确认：毛趣映画因资质原因隐藏的「交友广场」完整业务族，全部纳入毛趣萌仔首版。页面、关联入口、互动能力、提醒与文案均在范围内；不能以只交付广场主页代替完整交付。下列内容是实施与验收要求，当前未实现、未验收。

## 1. 页面和入口

| 范围 | 桌面端要求 | 验收重点 |
| --- | --- | --- |
| 交友广场主页 | 候选宠物、喜欢/跳过、地区与偏好筛选、自己的交友资料与联系方式设置 | 空池、加载失败、重复操作、多宠物切换及资料未完善均有明确处理 |
| 我的匹配 | 已匹配、已发送、被拒绝、待处理；查看申请、同意/拒绝、撤回及解除匹配 | 双端状态一致，过期通知与并发操作不能恢复已失效的关系 |
| 我的收藏 | 收藏、取消收藏、查看档案及适用的举报操作 | 已隐藏、删除、被拉黑或失去可见权限的宠物正确处理 |
| 交友黑名单 | 列表、拉黑、解除拉黑 | 按用户关系生效；解除拉黑不自动恢复旧匹配或申请 |
| 附近的小朋友 | 工作台发现区域提供附近宠物推荐及进入档案的入口 | 地区数据缺失可设置；按现有地区推荐，不伪造精确距离 |
| 广场宣传入口 | 工作台发现区域提供交友广场卡片/Banner | 能进入完整广场；不机械照搬小程序的页面尺寸 |
| 提醒筛选与分组 | 提醒中心包含交友筛选、交友提醒分组 | 待处理与普通动态区分，处理后及时更新 |
| 交友角标 | 工作台/提醒入口显示真实可处理交友事项数 | 不把历史喜欢或已处理匹配长期计为待办；跨入口一致 |
| 公开宠物档案「喜欢」 | 恢复爱心按钮与对应热力信息 | 档案点赞与交友申请是不同业务动作，遵守各自规则 |
| 公开档案「更多」 | 同时提供适用的举报和拉黑操作 | 自己的档案、无权访问和已拉黑场景正确处理 |
| 旧链接、分享与深链接 | 为桌面路由建立对应目标；校验登录、资源与权限，失效时提供可用返回入口 | 不出现死链、空白页或绕过授权；不改动小程序仍需隐藏的路由策略 |

入口与页面存在重叠，不按“约 20 项”的加总作为交付依据，以上功能和下列业务链路必须逐项验证。宠物点击后的快捷入口保持轻量，完整交友页面放在独立工作台。

## 2. 业务能力与数据规则

| 能力 | 实施与验收要求 |
| --- | --- |
| 档案、交友资料与偏好 | 真实账户的宠物档案查看/编辑/选择；交友资料覆盖现有物种、年龄/生日、性别、绝育状态、地区、社交宣言与偏好。交友公开须由用户主动开启；公开档案与加入交友候选池分别处理。默认桌宠形象不自动成为真实宠物交友档案。 |
| 喜欢与跳过 | 保留候选过滤、已有关系判断、重复请求幂等、拒绝后的冷却、每日次数和操作频率；免费功能不扣积分，不自动取消既有限制。 |
| 申请与匹配 | 完整覆盖发起、待处理、已发送、拒绝、接受、撤回、互相喜欢形成匹配、解除匹配；以服务端状态为准。喜欢发出申请不等于立即向对方公开联系方式。 |
| 收藏 | 添加、取消、跨端一致；遵守可见性与拉黑规则。 |
| 联系方式交换 | 支持微信号、手机号和联系方式二维码；本人可编辑，只有满足匹配与授权条件的参与者可查看对方信息。解除匹配、拉黑或权限撤销后阻止继续从服务端读取。已被对方复制或保存的内容不能承诺远程收回。 |
| 拉黑与解除 | 延续服务端的用户级隔离与关联关系处理；验证候选、附近推荐、收藏、匹配、申请、联系方式各处一致生效。 |
| 举报 | 覆盖档案、匹配、申请与收藏中适用的举报入口；提交、失败重试、受理状态与现有审核处置链路衔接，不能只弹“提交成功”而不落库。 |
| 附近推荐 | 延续已有省/市/区与公开资料过滤。附近推荐与交友候选池的资格条件分开，不擅自将两者等同。 |
| 交友提醒 | 展示申请、匹配与喜欢等现有提醒类型；通知点击进入正确对象；支持免打扰、处理状态刷新、断线重连和双端并发去重。服务端关系状态共享；本地通知记录遵守本地数据原则。 |

## 3. 现有能力与需要补齐的部分

小程序前后端仅作为只读分析来源，不在本次范围确认中修改。现有 `/pet-social/*`、`/pets/nearby`、公开档案和 `/reminders` 可作为业务复用起点；桌面端自行实现界面和客户端适配。

- **联系方式二维码需要新增。** 当前后端 `app/schemas/pet_social.py` 的 `SocialContactType`、`app/models/pet_social.py` 的联系方式枚举以及 `app/services/social_contacts.py` 的校验仅包含 `wechat`、`phone`。须补齐数据迁移、上传/替换/删除、受权查看与失效处理；二维码图片不进入公开档案、公共列表或永久公开下载地址。支持用户提供的联系二维码，不把普通微信号编码成二维码冒充微信加好友码。该要求与邮箱“大号数字验证码、一键复制”相互独立。
- **桌面登录与设备会话需要新增。** 绑定同一毛趣映画账户，支持过期、退出与撤销；不读取小程序缓存冒用其登录状态，不把微信 `session_key` 刷新当作桌面会话刷新。
- **终端开关需要明确。** 保留小程序 `FEATURE_PET_SOCIAL=false`；桌面入口独立控制，服务端依据可信身份与设备会话执行权限，不仅依赖前端开关或任意客户端请求头。桌面迁移本身不构成上线资质结论，发布条件另行核实。
- **提醒去重与处理同步需要补齐。** 现有提醒查询不等于已提供统一的已读、通知投递或确认机制。实现前确定稳定事件标识、处理状态与本地投递记录，验收双端重复投递和并发处理；无需为此上传全部本地通知历史。
- **安全与审核链路需要桌面适配。** 保留所有权校验、联系方式受限读取、举报落库及实际审核处置；核实既有内容审核服务在桌面登录下的身份适配，不能因原来依赖微信身份就直接跳过审核。

共享云端内容限于此业务需要的账户、宠物档案、主动公开的交友资料、关系、联系方式、举报与处理状态。邮件、剪贴板、个人文件等本地工具数据不因启用交友而上传。

## 4. 文案与非目标范围

工作台发现页、提醒空状态、关于、帮助及相关活动地址说明同步补全交友描述；桌面快捷入口、工作台和通知跳转的说明应符合实际交互，不照搬微信 tabBar 操作说明。此处不要求恢复小程序线上入口或修改其文案。

本次扩充针对交友广场完整业务族。漫画的产品暂缓、通用分享调整、AI 标识调整以及其他类目审核状态，不因此自动变成待迁移模块；原已确定的桌面功能继续按实施交接执行。
