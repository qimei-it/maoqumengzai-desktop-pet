- 产品名称：毛趣萌仔。
- 定位：毛趣映画微信小程序的配套桌面宠物，提供情感陪伴、桌面效率工具；宠物档案与宠物交友业务在绑定账户后开放，其中交友广场不在首个公开开源版本交付。
- 桌面项目：`/Users/liyifan/Documents/Workspace/Project/electron-project/maoqumengzai-desktop-pet`。
- 小程序后端：`/Users/liyifan/Documents/Workspace/Project/wechat-miniprogram/maoquyinghua/maoquyinghua-backend`。
- 小程序前端：`/Users/liyifan/Documents/Workspace/Project/wechat-miniprogram/maoquyinghua/maoquyinghua-frontend`。
- 旧桌面目录 `maoquyinghau-desktop-pet` 不作为本次默认实现目录。
- 技术方向：Electron + Vue 3 + TypeScript；构建、状态、数据库、进程与安全边界已记录到 [技术方案](technical-architecture.md)，候选精确版本已核实公开元数据，P1 初始化时执行安装与组合构建验证。

## 2. 用户确认的关键边界

### 2.1 桌宠与工作台

- 2D 透明背景；默认麻薯沿用当前美术风格。后续用户生成的宠物可选择自己的美术风格，不再全局固定 2.5D 像素风或统一像素网格。
- 桌面体量和身体比例以用户所指 Codex 桌宠观感为参考；本次未量测其准确尺寸，不能宣称已有精确像素规格。
- 宠物常驻桌面；点击打开聊天与工具快捷入口；完整功能进入独立工作台。
- 面板视觉统一沿用毛趣映画小程序前端的颜色、字阶、圆角、按钮/卡片与主题规范，按桌面尺寸和鼠标/键盘交互适配；宠物图像保持独立，规则见 [面板样式统一](design/panel-style-contract.md)。
- 图标沿用 Lucide.dev + Firefox Emoji；当前功能性图标使用官方 Lucide SVG，彩色情绪/业务素材按需采用 Firefox Emoji 并保留来源声明，见 [图标规范](design/icon-system.md)。
- 首版不穿衣、不提供换装服务。
- 首版默认角色只保留黏人的布偶猫「麻薯」；柯基犬延后到后续版本。
- 默认角色直接可用，未配置 DeepSeek Key 也可使用免费工具和宠物互动。
- 性格体现在动作频率、节奏、表情以及角色回复中，不靠持续打扰体现。

### 2.2 本地与云端

用户明确强调：安装设备上的本地数据默认不上传云端，该离线的数据必须离线保存。

| 数据或能力 | 边界 |
| --- | --- |
| 番茄钟、饮水、休息提醒、待办及其历史 | 本地保存、离线可用 |
| 剪贴板、截图、文件置物架、转换文件、转换历史 | 本地保存与处理 |
| 邮箱凭据、邮件缓存、数字验证码 | 本地保存；客户端直接连接邮箱服务 |
| 播放控制、歌词缓存、人工匹配和时间偏移设置 | 本地处理；开启在线查词后直连歌词提供方 |
| OpenAI 本地登录凭据、额度缓存 | 仅本机使用；查询直连对应服务 |
| 宠物动画资源、日常行为与提醒规则 | 本地运行，不自动请求模型 |
| 宠物档案、交友广场、交友处理状态 | 复用小程序云端业务数据；交友广场后续开放，不在首个公开开源版本交付 |
| 新 DeepSeek 会话 | 云端同步，支持小程序与桌面继续同一会话 |
| 专属宠物制作 | 用户主动发起云端生成；使用选定的档案图片；完成后交付可下载、本地播放的资源包 |
| 用户 DeepSeek Key | 本机用于余额查询；跨端聊天按已讨论的安全托管方案供后端调用，明确用途并提供替换、解绑、删除 |

- 本地数据不得经日志、故障报告、遥测或自动备份间接上传。
- 本地文件拖给宠物用于转换或放入置物架，不自动进入 AI 聊天，不自动上传附件。
- “本地保存”不等于“所有功能无须联网”：收邮件、在线查词、额度查询仍需连接相应提供方。
- 云端同步采用业务白名单，不做整个本地数据库的自动同步。

### 2.3 费用

| 行为 | 用户费用 |
| --- | --- |
| 默认桌宠、已有动画播放、日常互动与规则提醒 | 免费 |
| 已确定的效率工具、文件转换、宠物档案、交友广场与交友提醒 | 不扣毛趣映画积分（交友广场后续开放） |
| 专属宠物形象与动画包制作、用户主动重新制作 | 扣绑定的毛趣映画小程序账户积分 |
| DeepSeek AI 对话 | 使用用户自己的 DeepSeek API Key，由 DeepSeek 结算，不扣平台积分 |

“只有自备 API 对话产生用户费用”的早期讨论，已被后续明确增加“专属宠物制作扣积分”这一要求修订。

- 不在后台调用模型生成饮水提醒、休息提醒、动画行为或普通完成提示。
- 不自动将 DeepSeek 会话切换到旧积分聊天通道。
- 标题、摘要、长期记忆等辅助模型调用如会产生费用，需要纳入明确的产品规则；首版可先用规则标题与最近对话上下文。

### 2.4 开源与功能开放

2026-11-12 确认：只交付一条公开开源的客户端代码线，不制作“开源版 + 闭源版”两个安装包；按能力分层开放。完整决策、仓库纪律与发布检查见 [开源策略与功能开放边界](open-source-strategy.md)。

| 能力 | 开放条件 |
| --- | --- |
| 桌宠、提醒、待办、置物架、剪贴板、截图、文件转换、音乐与歌词、邮箱收件 | 无需账号，离线可用，作为获客入口 |
| 账号绑定、设备会话、宠物档案查看/编辑/选择、云端同步、新 DeepSeek 会话、专属制作 | 绑定毛趣映画账户，服务端逐次校验身份与资源归属 |
| 交友广场、附近推荐与社交提醒 | 仅对已绑定账户开放；首个公开开源版本不交付，开放节奏由服务端运营开关控制 |

- 接口地址不视为秘密，客户端不存放任何密钥；安全边界由服务端授权、设备会话、归属校验与限流承担。
- 公开仓库是私有主仓库的发布镜像；客户端核心采用 MIT 或 Apache-2.0，允许官方与私有构建。
- 云能力统一经 `cloud-adapter` 接口接入，官方实现单独成模块，保留将来私有构建的退路，但当前不建设双版本。

## 3. 默认角色与专属制作

### 3.1 用户提供的参考图

- [布偶猫参考](references/default-ragdoll-reference.png)：蓝眼睛、奶白与浅棕毛色、蓬松胸毛、大尾巴。
- [柯基参考](references/default-corgi-reference.png)：黄白毛色、额头白色中线、立耳、圆眼睛；补全自然四足短腿长身体型。
- 两张图只作为角色外观参考；默认麻薯沿用当前风格，柯基及后续自定义宠物不强制固定美术风格。
- 柯基参考中的卫衣、背景、图标、装饰均不进入角色；两只均不加衣服。
- 参考图是用户提供的原始图片副本，不是已完成的桌宠素材，未执行生成或编辑。

### 3.2 专属制作流程

- 用户从自己的宠物档案选择已有图片，无需先自行制作多视图或动画帧。
- 调用平台火山方舟图像生成模型，使用小程序积分结算。
- 先确认稳定角色形象，再以该形象为参考生成动作素材，减少毛色、花纹、比例变化。
- 后处理需要处理透明通道、尺寸、脚底锚点与裁切；像素风宠物可选用统一像素网格，其他风格不强制。首版不做帧动画，循环衔接仅在后续需要时验证。
- 模型的“组图”不等于已经合格的连续帧动画；模型版本、动作一致性与透明输出能力须通过样例验证。
- 用户操作建议：选图 → 查看积分报价 → 发起制作 → 查看结果 → 下载并启用。
- 已讨论建议：预占积分，成功交付后结算，系统失败释放预占；人工不满意后的重做规则、包内动作数量与积分定价仍需明确。
- 默认角色由项目预制，用户无需为首次使用默认角色发起制作任务。

### 3.3 动作与行为基线

首版只保留现有姿势与程序化动效，不做新动作或帧动画；精确帧数、时长与频率不再作为首版要求。

| 场景 | 首版范围 |
| --- | --- |
| 待机 | 现有 base/blink + CSS 呼吸、摇摆与定时眨眼 |
| 拖动 / 放下 | 现有 lifted 姿势 + 摇摆 |
| 听歌 | 现有 music 姿势 + 缓慢摇摆 |
| 聊天 / 智能体 | 现有 ponder 姿势 + 倾斜 |
| 专注 | 现有 focus 姿势 + 呼吸 |

- 默认在用户放置区域陪伴；首版不做限定区域散步或全桌面漫游。
- 全桌面漫游、行走与转身不在首版范围。
- 单击打开快捷面板，拖动改变位置；首版不做抚摸手势。
- 专注和免打扰减少动作与气泡；首版不做休息/醒来。
- 用户拖动、文件投递等主动操作优先响应；后台任务不因宠物切换动作而中断。
- 爬窗口、识别窗口边缘、攀爬任务栏未纳入首版已确认范围。

## 4. 完整功能范围：不因分批交付删减

### 4.1 宠物、账号与聊天

- 云能力仅在绑定毛趣映画账户后可用；未绑定账户时客户端保持本地功能完整可用，不做登录墙。
- 账户绑定、登录、退出、设备会话撤销与宠物选择。
- 复用小程序宠物档案和性格，桌面动画资源单独管理。
- 首版 AI 对话只支持用户自备 DeepSeek API Key。
- 新增独立 DeepSeek 对话服务，与小程序原有积分对话的模型调用、会话和计费明确区分。
- 新会话出现在小程序宠物分身入口并支持继续；旧会话不自动混入新会话上下文。
- 需要安全密钥托管、流式回复、会话持久化、上下文管理与用量反馈。
- 处理两端并发发送、断线、取消、重连、重复提交和重复生成风险。

### 4.2 十一项效率能力

| 功能 | 第一版范围 |
| --- | --- |
| 番茄钟 | 专注/休息、自定义时长、暂停恢复、记录统计；宠物状态联动 |
| 饮水提醒 | 时段、间隔、饮水记录、每日目标、延后/关闭 |
| 休息提醒 | 久坐/用眼提醒、延后、免打扰 |
| 待办清单 | 新增编辑、完成、截止时间、重复规则、到期提醒 |
| 音乐 | QQ 音乐、网易云音乐、Apple Music、酷狗音乐；上一首、下一首、播放/暂停、当前歌曲和歌词文本 |
| 文件置物架 | 拖入文件或文件夹、定位、拖出文件、移除记录；文件夹只保存引用，不支持拖出与格式转换 |
| 剪贴板 | 文本/图片历史、搜索、固定、重新复制、清空、敏感内容排除 |
| 截图收集器 | 快捷截图、框选、多屏、预览、复制、保存、拖出，联动置物架 |
| 邮箱收件 | 首批 QQ、163、Outlook、Gmail；多账户、未读提示、列表、正文和附件处理 |
| 邮箱验证码 | 识别验证码邮件；大号数字验证码、一键复制；避免把订单号等误识别为验证码；提供时间与过期处理 |
| AI 额度查询 | OpenAI 本地订阅额度；DeepSeek API 余额 |

- 音乐需求已收敛为播放控制与歌词；首版不要求系统音频采集或真实节拍识别。可用本地播放状态驱动轻微宠物动作。
- 四款播放器都是双平台适配目标，尚未完成兼容测试，不能把“系统有媒体 API”视为每款播放器已支持。
- 邮箱授权方式与协议需要逐家核实；不要假定四家都能使用普通密码 IMAP 登录。
- 用户已澄清需要的是“大号数字验证码＋一键复制”，不需要生成二维码。

### 4.3 AI 额度与歌词

- OpenAI：根据本地 Codex / ChatGPT 可用登录状态读取实际可访问的订阅额度；不要求 OpenAI API Key 查询余额。
- Claude：不再接入；不实现 Claude 额度读取，也不要求 Anthropic API Key。
- DeepSeek：用户 API Key 查询余额，由桌面直接请求。
- 登录状态可检测不代表一定能读取额度；需按客户端与版本分别验证。
- 额度卡片明确来源、账户、周期、剩余比例、重置与更新时间；缺失字段不能显示为无限额度。
- 本地账号切换、退出或凭据失效后清除旧账户状态；不修改原客户端凭据、不将其上传自家服务器。
- OpenAI 提供方接入方式及其适用范围需要验证；不直接复制岛仔的私有接口、凭据解密或身份伪装实现。
- 歌词技术建议：本地歌词/缓存优先，LRCLIB 主来源，AMLL 补充。用户尚未单独确认固定选用次序，Agent 可将此作为有实测依据的初始方案。
- 详细样例、结果、接口文档与局限见 [歌词 API 调研](research/lyrics-api-evaluation.md)。
- LrcShare 仍需申请程序 Key 和确认用途；歌词迷样例探测有 404、503 与 TLS 错误，目前不作为发布依赖。
- 免费 API 的可调用性不等于已确认所有歌词展示与缓存使用范围；正式发布前核对提供方条件。

### 4.4 文件转换

- 主要入口是“将文件拖给桌宠”，不用 Filee 的轮盘交互。
- 接收卡展示类型和可执行目标；允许选择转换或放入置物架。
- 文件直接拖到桌宠身上后，在桌宠旁显示文件置物架；保存/转换操作就近完成，拖出时按住文件卡片、图标或文件名本身，不要求拖动专门按钮。技术验证台不是正式版页面，不作为日常文件流程入口。
- 支持进度、取消、批量队列、重名处理和结果打开/定位/复制/拖出，默认保留原件。
- 首版候选：常见图片互转与压缩、HEIC 转常用图片、PDF 与图片互转/合并/拆分/提取文字、Office 转 PDF、旧 Office 格式转新版、OFD 转 PDF/图片、常见影音转换与提取音频、ZIP/7Z 打包和常见压缩包解压、TXT/Markdown/HTML 与 CSV/Excel 的常用转换。
- 排除用户入口中的 HWP/HWPX 韩文办公、CAD、三维、地理信息、字体、医疗科研和专业广播影音格式。
- 最终必须建立方向明确的输入→输出白名单；不能把候选格式理解为任意互转，也不凭讨论承诺复杂文档无损转换。
- WPS/ET、旧 Office、OFD 的实际兼容性与 OCR、PDF 转可编辑文档能力需样例验收后开放。
- Filee 内部部分 Office→PDF 路线使用 HWPX/rhwp 作为中间步骤；隐藏韩文格式入口不等于可以直接删掉所有相关依赖。选用哪条路线需评估后记录。
- 转换由本地独立进程处理；按用户 2026-11-09 确认，每个安装包内置对应平台/架构的全部首版转换引擎及必要运行时、资源，支持安装后首次使用即离线转换；核对平台、来源、版本、校验和与分发许可，不要求另行下载引擎。
- 直接分发 Windows 安装程序与 macOS DMG；本地历史、缓存、素材保存在系统应用数据目录，设置提供清理与打开目录；导出文件由用户选择保存位置。

### 4.5 小程序业务与设置

- 首版范围调整为：账号绑定、设备会话与宠物档案（查看/编辑/选择）进入首个公开开源版本；因资质隐藏的完整交友业务族移出首版，保留为后续开放项，详细范围与验收见 [完整交友模块](social-module-v1-scope.md)。
- 交友广场的页面、入口、角标、提醒分组与深链接在首个公开开源版本均不出现；相关范围不删除，实现前不勾选验收项。
- 后续开放需同时具备服务端授权、资质与审核结论；开放范围由服务端运营开关控制，不靠修改客户端绕过。

### 5.2 命名

用户于 2026-11-09 明确更新：桌面项目统一使用 `mqmz`（毛趣萌仔）作为标识前缀，替代此前约定。共享小程序业务表与第三方协议字段仍遵守各自规范。

| 场景 | 约定示例 |
| --- | --- |
| Electron IPC | `mqmz:mail:code-detected` |

- 现有共享业务数据库遵循原仓库的语义化表名约定，不为了桌面前缀全库改名。
- 第三方协议字段保持原格式，进入内部模型时映射。

### 5.3 建议工程边界

这是实施建议，不代表代码结构已经存在：

- Electron 主进程：窗口、托盘、通知、权限、凭据、文件与原生服务入口。
- 受限 preload / 类型化 IPC：只暴露明确业务能力，验证调用来源、参数和路径。
- 渲染进程：宠物、快捷面板、工作台及设置；不直接持有任意本机执行权限。
- 本地服务与存储：调度、待办、剪贴板、邮箱、音乐、额度、转换任务与缓存。
- 独立任务进程：重型转换、素材处理等，避免阻塞窗口和宠物动画。
- 云端接口：账号/设备绑定、既有宠物与交友业务、新 DeepSeek 会话、积分与专属制作。
- mock / 演示态与真实连接态必须可辨认；不能以静态页面或假数据代替功能验收。
